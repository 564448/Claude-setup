# General skills

User scope: linked into `~/.claude/skills`, so they load in every folder, not just `C:\Knight\Claude`.

- **[coding-guidelines](./coding-guidelines/SKILL.md)**: behavioral guidelines against common LLM coding mistakes. Think before coding, keep it simple, make surgical changes, and define verifiable success criteria. **Use whenever writing code.** Forked on 2026-09-24 from the `andrej-karpathy-skills:karpathy-guidelines` plugin (forrestchang/andrej-karpathy-skills v1.0.0, MIT). That plugin is now disabled in `~/.claude/settings.json` so the skill doesn't load twice. Re-enable it only if you delete this fork.
- **[remote-pi-min](./remote-pi-min/SKILL.md)**: SSH/SCP into the Raspberry Pi "min" (`min@masterpi.local`) with the pre-authorized key, so no password is needed. Used for UAV camera/TFLite work.
- **[remote_vm_kali](./remote_vm_kali/SKILL.md)**: SSH/SCP into the Kali VM (`kali@192.168.41.128`, a static IP set on the VM's `eth0`). Prefers the key (`~/.ssh/id_ed25519_kali`, alias `kali-vm`) and falls back to password `kali`/`kali`. Used by the Cyber project.
- **[upload-to-github](./upload-to-github/SKILL.md)**: preps a folder for GitHub and pushes it. It runs static code checks, writes a README, and adds `.gitignore` + `LICENSE` (checking upstream licenses for derived code), then pushes via `gh`. Always confirms before pushing.
- **[root-cause-debugging](./root-cause-debugging/SKILL.md)**: debugging discipline for any bug, failing test/build/DRC or flaky behaviour. It recites a 5-line marker (`[root-cause-debugging]`) once per debug session so you can see the skill loaded, then works five steps: reproduce (raise the rate if flaky, stop if none), map the fail path (debugger → knobs one at a time → compare with a working case → `[DBG-xxxx]`-tagged probes), rank 3–5 hypotheses and run the disproof first, keep a run ledger every hypothesis must fit, then make one fix at the root and stop to rethink after 3 failed fixes. Written 2026-09-27 from the ideas of obra/superpowers `systematic-debugging` (MIT) and thananon/9arm-skills `debug-mantra` (no license, so ideas only, no copied text). Hands off to `verification-before-completion` at the fix step.
- **[verification-before-completion](./verification-before-completion/SKILL.md)**: gate before any "done / fixed / passing" claim, commit, upload or end-of-task summary. Identify the check that proves the claim, run it fresh, read the full output, then report the real status. A domain skill's own verification standard (e.g. `pcb-autoroute` §4) takes priority over the generic evidence table. Ends with a **[Verified]** block listing the checks run and anything left unverified, which also shows the skill loaded. Forked on 2026-09-27 from obra/superpowers `verification-before-completion` (MIT); PCB/.docx-specific rows were left out on purpose because their standards live in their own skills. `C:\Knight\Claude\CLAUDE.md` "End-of-task summary" points to it.
- **[grilling](./grilling/SKILL.md)**: a relentless interview that stress-tests a plan, decision or idea before anything is built. It maps the plan as a design tree, then asks in rounds: each round is every question whose prerequisites are settled, numbered, with Claude's recommended answer (worded so "yes" accepts it). Claude looks up facts itself and leaves only decisions to you, and must not act until you confirm a shared understanding. Can also trigger on "grill" phrases. Forked on 2026-10-15 from mattpocock/skills `skills/productivity/grilling` @ 49dd158 (MIT). Text unchanged except the round format: on 2026-10-15 the ❓/➡️ emoji were replaced with `**Q1 - title**:` and `**Recommended:**` (no emoji in skill output).
- **[grill-me](./grill-me/SKILL.md)**: the `/grill-me` front door to `grilling`. User-invoked only (`disable-model-invocation: true`); its whole body just loads `grilling`, so don't delete one without the other. Forked on 2026-10-15 from mattpocock/skills `skills/productivity/grill-me` @ 49dd158 (MIT).
- **[skill-intake](./skill-intake/SKILL.md)**: `/skill-intake <link or name> [install method]`, user-invoked only (`disable-model-invocation: true`). With no link or name it replies `[Invalid command]` and stops. Phase A reads the real source (files, LICENSE, commit, hooks/SessionStart/MCP, runtime needs), explains when it runs, compares it with `CLAUDE.md`, the index and overlapping own skills, and reports under a `[skill-intake]` summary line with tiered recommendations, then stops to ask. Phase B installs only the chosen way (fork / ideas only / npx / plugin / MCP-only by license), registers it in both indexes, runs `link-skills.ps1`, and finishes with `verification-before-completion`. If the install method is given in the arguments it skips the question unless it finds a blocker. Written 2026-10-15 from the steps used on superpowers, debug-mantra, context-mode and grill-me.
- **[distill-memory](./distill-memory/SKILL.md)**: `/distill-memory [topic]`, user-invoked only (`disable-model-invocation: true`). Reads the user's messages from the whole session (including before compaction, via the transcript `.jsonl`), proposes a grouped summary of lasting guidelines, then a file plan, and writes only after confirmation in every permission mode. Every topic gets its own memory folder with a `README.md` index and one line in `MEMORY.md`; the user names new folders (Claude proposes 1–3), and any change to an existing memory is shown side by side with options and pros/cons first. Everything in English. Ends with `verification-before-completion`. Written 2026-10-17 from the steps used to build the `UAV/` memory folder.
